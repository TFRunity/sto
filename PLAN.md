# План разработки v1 — неделя 1 (сквозная оплата)

Составлено 30.10.2026. Режим работы — **B + C** (`AGENTS.md`): Go-логику пишет разработчик,
агенты — инфраструктуру, SQL, контракт, скелеты, ревью.

## Текущий статус

Вечера 1 и 2 закрыты по сообщению разработчика. Gateway реализован с отличиями от
чернового плана. Автоматические тесты вечера 2 отменены. В Gateway оставляем `decideRequest` обычной функцией. В вечере 3 Orders прочитает
идентичность в хендлере создания заказа. Общий middleware отложен.

## Рамки

- **Время:** 7 вечеров × 2–4 ч ≈ **20 ч** Go-логики разработчика.
- **Цель недели:** сквозной сценарий оплаты через nginx → Gateway, в docker compose:
  регистрация клиента → инженер создаёт заказ → добавляет товары (цена фиксируется) →
  клиент оплачивает → сага списывает товар в Inventory → справка PDF скачивается.
  Плюс отказной путь: Inventory недоступен → дедлайн 10 с → заказ снова `active`.
- **Критерий готовности:** агентский smoke-скрипт (`scripts/e2e.sh`, curl) проходит оба пути.

## Что входит / что откладывается

| Входит в неделю 1 | Откладывается на неделю 2+ |
|---|---|
| `chassis`: конфиг, логи, конверт ошибок, middleware идентичности, shutdown, outbox, RabbitMQ (публикация + потребление), адаптер Gotenberg | Сервис **Vehicle** (фото, карточка ТС) — `vehicle_id` в заказе берётся из seed |
| **Users**: регистрация, вход (JWT) | Сервис **Services** (услуги) — в заказе только товары |
| **Gateway**: JWT, таблица ролей, прокси с allowlist заголовков | Дашборд, поиск директора (ADR-032, ADR-039) |
| **Inventory**: цена товара по id, консьюмер `DeductStock` / `CancelStock` с идемпотентностью | CRUD каталога (товары заводит seed-миграция) |
| **Orders**: создание заказа инженером, добавление товара, чтение заказа, оплата (старт саги), консьюмер ответов, воркер дедлайнов, воркер справок, скачивание справки | Заявка клиента + claim, этапы работ, отмена, `engineers-load`, stats |
| Тесты доменных функций (ADR-013, ADR-031) | Проверка soft delete в CI, CI целиком (локально — `make lint test`) |

Сокращение маршрута: клиентская заявка + claim заменены на «инженер создаёт заказ сразу
`active`» (`sequence-create-order`) — один шаг вместо двух. Инженер и товары — в seed.

## Вечера — разработчик (≈ 3 ч каждый)

После каждого куска — ревью агентом (C): сверка с ADR и `decisions/`, `make test lint`.

Задачи вечера — `tasks/evening-<N>.md` (вечер 1: `tasks/evening-1.md`).

| Вечер | Что пишешь | Готово, когда |
|---|---|---|
| **1** | `chassis`: загрузка конфига из env (`errors.Join`), slog, конверт ошибок + запись ответа, middleware идентичности (`X-User-Id/Role` → контекст, 401), graceful shutdown. **Users**: регистрация (bcrypt, 409 phone_taken), вход (JWT HS256) | `curl` в Users напрямую: регистрация и вход работают |
| **2** | **Gateway**: проверка JWT (`WithValidMethods`), таблица «префикс → роли» deny-by-default, `ReverseProxy` с `Rewrite` и allowlist заголовков, `X-Request-Id` | Регистрация/вход и закрытый маршрут через nginx; подмена `X-User-Role` клиентом не работает |
| **3** | **Inventory**: `GET` цены по id. **Orders**: создание заказа инженером (+ `order_engineers`, 1 tx), добавление товара (цена по HTTP до tx), чтение заказа с суммой. Доменные функции суммы и `canStartPayment` + табличные тесты | Инженер создаёт заказ и добавляет товары через Gateway, сумма верна |
| **4** | `chassis/outbox`: вставка в переданной tx (`DBTX`), воркер (тик, пачка, confirm на сообщение, `published`). `chassis/rabbit`: публикатор с confirms, консьюмер (prefetch 1, ack после коммита, 5 доставок → ack + лог) | Тестовое сообщение проходит outbox → RabbitMQ → консьюмер |
| **5** | **Сага**: оплата в Orders (tx: `paid` + `saga_state` + outbox, 202). **Inventory**: `decide(попытка, команда)` + полная табличная проверка, списание `quantity >= N`, `stock_attempts`, ответ через outbox. **Orders**: консьюмер ответов (условный UPDATE `current_step`, компенсация) | Оплата → `completed`, остаток уменьшился; дубль команды не списывает второй раз |
| **6** | **Воркер дедлайнов** + `CancelStock` в Inventory (возврат, tombstone). **Справка**: `INSERT pending` в tx завершения саги, воркер справок (попытки, пауза), адаптер Gotenberg, скачивание PDF | `e2e.sh` — оба пути зелёные |
| **7** | Буфер: исправления по ревью, прогон отказов (стоп Gotenberg → 3 попытки → `failed`), чистка | Неделя закрыта |
