# ADR-021: Статус заказа и этап работ — две независимые оси

## Статус
Принято

## Контекст
Документы расходились: sequence-диаграммы (оплата, справка, заявки)
используют `requested → active → paid / cancelled`;
`director-web-design.md` утверждал, что `paid` убран в пользу
`completed`; RN-дизайн использовал лейблы «в работе / готов / ожидает
оплаты / выдан». Отдельно существовал use case «Изменить статус ТС» без
определённого списка статусов и связи со статусом заказа (TODO §1).

## Решение
1. **Статус заказа** (жизненный цикл и деньги):
   `requested → active → paid`, плюс `cancelled` из `requested`/`active`.
   `paid` — финальный статус. Компенсация саги оплаты: `paid → active`.
   Статуса `completed` нет.
2. **Этап работ** — отдельное поле заказа `stage`:
   `принят / в_работе / готов / выдан`. Меняет инженер
   (`PATCH /orders/{id}/stage`, `sequence-change-work-stage`).
   Переходы не ограничены, единственное правило — `выдан` только при
   `status = paid` **и успешно завершённой саге оплаты** (иначе 409).
   Уточнено 30.10.2026 (D-09, ADR-030): после старта саги заказ уже
   `paid`, но до ответа Inventory (≤ 10 с) оплата может откатиться.
3. **У ТС статуса нет.** Состояние «в ремонте» принадлежит конкретному
   визиту (заказу), а не машине. Use case «Изменить статус ТС»
   переименован в «Изменить этап работ».

Производные значения для UI: «Ожидают оплаты» = `active` + этап
`готов`; «Выдан» = этап `выдан`.

## Альтернативы, которые рассматривались
- **`paid` + `completed` в статусе заказа** (выдача как переход
  статуса) — отклонено в пользу отдельной оси этапа.
- **Как в director-web: `active / completed / cancelled`** — отклонено:
  компенсация `completed → active` семантически странная, пришлось бы
  переделывать сагу оплаты и справку.
- **Статус на Vehicle, независимый от заказа** — отклонено: две state
  machine в двух сервисах без синхронизации; «выдан» навсегда висит на
  машине до следующего визита.
- **Убрать статус совсем** — отклонено: клиент не узнаёт, что машина
  готова.

## Последствия
**Плюсы:** сага оплаты и справка не меняются; всё состояние визита —
в Orders, без межсервисной синхронизации; возвращены «готов» и
«выдан».

**Минусы:** у заказа две оси состояния, правило «выдан ⇐ paid» держится
кодом Orders.
