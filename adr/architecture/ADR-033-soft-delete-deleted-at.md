# ADR-033: Soft delete — колонка `deleted_at`, частичные уникальные индексы, проверка в CI

## Статус
Принято

## Контекст
На пользователей, машины, товары и услуги ссылаются старые заказы
(ссылки по uuid без FK, ADR-007). Физическое удаление оставило бы в
истории «машина: ???». Повторное добавление удалённой сущности (тот же
госномер, тот же телефон) не должно упираться в уникальность удалённой
записи.

## Решение
- Soft delete у **пользователей, машин, товаров, услуг**. Заказы не
  удаляются: у них терминальный статус `cancelled`.
- Колонка **`deleted_at timestamptz`** в самой таблице сущности (рядом с
  `created_at`, `updated_at`); `NULL` — запись жива.
- Уникальные индексы — **частичные**, только среди живых:
  ```sql
  CREATE UNIQUE INDEX uq_vehicles_number ON vehicles (number) WHERE deleted_at IS NULL;
  CREATE UNIQUE INDEX uq_users_phone     ON users (phone)     WHERE deleted_at IS NULL;
  ```
  Госномер перед записью нормализуется (ADR-031).
- Фильтр `deleted_at IS NULL` пишется **в каждом** SQL-запросе sqlc.
  Запросы, которым нужны удалённые записи (история), помечаются
  комментарием `-- include-deleted`. Соблюдение проверяет CI (ADR-014).
- При удалении в outbox может уходить событие «удалено» (только id),
  если другим сервисам это нужно.

> Решение А-03 (принято 30.10.2026): решение D-08 называло уникальность «госномер,
> email», но у пользователя в модели нет email — логин идёт по телефону
> (`sequence-register`, `sequence-engineer-login`). Уникальным среди
> живых сделан **телефон**.

## Альтернативы, которые рассматривались
- **Флаг `deleted boolean`** (как было на диаграмме классов) — дата
  удаления пригодится при разборе «куда делась машина». Заменён.
- **Views с фильтром** — отклонены (антипаттерн по мнению разработчика).
- **Склеивание запросов в Go** — ломает статический SQL sqlc (ADR-024).
- **Архивная таблица `*_deleted`** — история требовала бы чтения из
  двух таблиц.

## Последствия
**Плюсы:** история заказов не ломается; повторное добавление сущности
возможно; забытый фильтр ловит сборка.

**Минусы:** проверка в CI текстовая, а не разбор SQL — нестандартный
запрос может её обойти.
