# Диагностика рабочей копии и локального запуска

Из корня репозитория:

| Команда | Что проверяет |
| --- | --- |
| `git status --short` | Изменённые и новые файлы. |
| `git diff -- orders inventory` | Незастейдженные правки отслеживаемых файлов двух сервисов. |
| `git diff --cached` | Правки, уже добавленные в индекс. |
| `git log -5 --oneline -- api/openapi.yaml` | Последние коммиты, затрагивающие контракт. |
| `rg -n 'GetItem' inventory` | Где объявляется или вызывается `GetItem`. |
| `go version` | Версия Go. Для сравнения с модулем выполни команду из каталога сервиса. |
| `gofmt -l users/internal/service.go` | Имя файла, если форматирование отличается. |
| `gofmt -w users/internal/service.go` | Форматирует указанный файл на месте. |
| `make ps` | Состояние контейнеров, включая остановленные. |
| `docker compose logs --tail=100 users` | Последние записи Users без ожидания новых строк. |
| `make logs SVC=users` | Последние записи и новые строки по мере появления. `Ctrl+C` завершает просмотр. |
| `ss -ltnp 'sport = :8081'` | На Linux показывает слушателя порта Users и процесс, если доступна информация о нём. |
| `curl -i http://127.0.0.1:8081/healthz` | HTTP-статус, заголовки и тело healthcheck Users при запуске на хосте. |

При падении сервиса сначала проверь его статус и логи. При `connection refused`
проверь порт и способ запуска. При `502` от Gateway сравни логи Gateway и
целевого сервиса, затем проверь адрес upstream для текущего режима запуска.
Адреса, сценарии Compose и примеры API собраны в [RUNNING.md](../../RUNNING.md).
