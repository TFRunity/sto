# Go в монорепозитории

У каждого сервиса свой `go.mod`. Корневой `go.work` объединяет модули для
локальной работы. Проверяй текущий модуль и workspace из каталога сервиса:

```sh
cd users
go version
go env GOMOD GOWORK
```

`GOMOD` показывает путь к `go.mod`, `GOWORK` — активный `go.work`.
Если команда смотрит на другой модуль, сначала проверь рабочий каталог.

## go mod tidy

После добавления или удаления импортов, в том числе в сгенерированных файлах,
синхронизируй зависимости конкретного модуля. Из корня репозитория:

```sh
(cd users && go mod tidy)
git status --short
git diff -- users/go.mod users/go.sum
```

`tidy` учитывает исходники и тесты, добавляет недостающие зависимости, удаляет
неиспользуемые и обновляет `go.mod` и `go.sum`. При отсутствии пакета в кэше
Go может обратиться к прокси модулей или репозиторию. Для нового сервиса запускай
`tidy` после генерации и появления импортов. Зависимость, на которую ещё нет
импортов, может исчезнуть из `go.mod`.

Для предварительной проверки используй `(cd users && go mod tidy -diff)` —
команда покажет предлагаемый diff без записи `go.mod` и `go.sum`. Если diff есть,
код завершения будет ненулевым. Если ошибка упоминает другой модуль или пакет,
сначала проверь первый проблемный импорт в сообщении. Сборка Docker работает
с `GOWORK=off`, поэтому при расхождении с локальным запуском проверь зависимости
в собственном `go.mod` сервиса и локальные `replace`.

## Сборка и тесты

Из корня репозитория:

```sh
(cd users && go build ./...)
(cd users && go test ./...)
(cd users && go test ./internal -run '^TestName$' -v -count=1)
```

`./...` охватывает пакеты модуля из текущего каталога. В последней команде
подставь имя нужного теста. `-v` показывает ход выполнения, `-count=1`
запускает тест без использования сохранённого результата. Проверь, что в выводе
есть строка `=== RUN` с нужным именем. Общие команды по модулям описаны
в [справочнике Make](make.md).

Примеры для существующих тестов, включая выбор подслучая, покрытие и детектор
гонок, собраны в [инструкции по тестам](tests.md).
