# Запуск тестов Go

Команды ниже запускаются из корня репозитория. Для быстрого прогона начни
с модуля, в котором менялся код:

```sh
make test MODULE=users
make test
```

Первая команда проверяет Users, вторая перебирает все модули. Для одного пакета,
теста или подслучая используй `go test` напрямую:

```sh
(cd users && go test ./internal)
(cd users && go test ./internal -run '^TestLogin$' -v -count=1)
(cd users && go test ./internal -run '^TestLogin$/^неверный_пароль$' -v -count=1)
```

- `./internal` выбирает один пакет, `./...` включает вложенные пакеты.
- `-run` принимает регулярное выражение. Часть после `/` выбирает подслучай
  из `t.Run`. Go заменяет пробелы в его имени подчёркиваниями.
- `-v` показывает имена запущенных тестов. Если видишь `[no tests to run]`,
  сверь выражение и пакет.
- `-count=1` отключает кэш результатов тестов для запуска. Строка `(cached)`
  без этого флага означает, что Go использовал результат предыдущего прогона.

## Дополнительные проверки

| Команда из корня | Когда применять |
| --- | --- |
| `(cd users && go test ./internal -list .)` | Узнать имена тестов верхнего уровня в пакете. |
| `(cd users && go test ./... -cover)` | Посмотреть покрытие операторов по пакетам. |
| `(cd users && go test ./internal -coverprofile=/tmp/sto-users-cover.out)` | Записать профиль покрытия пакета для разбора. |
| `(cd users && go tool cover -func=/tmp/sto-users-cover.out)` | Прочитать профиль по функциям. |
| `(cd users && go test -race ./...)` | Искать гонки данных на путях, которые выполняются в тестах. Требуются поддерживаемая платформа, CGO и C-компилятор. |

`TestLogin` использует fake-репозиторий и запускается без PostgreSQL и Compose.
Отладка этого теста с точкой останова описана в [Delve](delve.md).
