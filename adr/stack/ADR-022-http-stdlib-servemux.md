# ADR-022: HTTP — stdlib `net/http` + `ServeMux` во всех сервисах

## Статус
Принято

## Контекст
Нужен HTTP-слой для шести Go-приложений. Gateway построен на
`httputil.ReverseProxy` и цепочке middleware, поэтому критична
совместимость с моделью `http.Handler`. Варианты: stdlib (`ServeMux` с
Go 1.22 умеет метод и `{id}` в шаблоне), `chi`, `Gin`, `Echo`.

## Решение
Во всех сервисах — stdlib `net/http` + `http.ServeMux`, без роутеров и
фреймворков.

Группы маршрутов и роли пишутся вручную по принципу **deny-by-default**:
один middleware над mux Gateway с таблицей «префикс → допустимые роли»
(ADR-019); неизвестный путь → 403; публичные маршруты (`/login`,
`/register`) помечены в таблице явно.

## Альтернативы, которые рассматривались
- **chi** — тонкая обёртка над `net/http`, группы маршрутов «из коробки».
  Отклонено: возможностей stdlib (метод + параметры пути) достаточно,
  лишняя зависимость не нужна.
- **Gin / Echo** — собственный контекст вместо `http.Handler`, хуже
  стыкуются с `ReverseProxy` и стандартными middleware, меньше учат
  стандартной модели. Отклонено.

## Последствия
**Плюсы:** ноль зависимостей; одна модель `http.Handler` во всех
сервисах и в Gateway; middleware переносимы.

**Минусы:** группировку маршрутов, биндинг и валидацию писать вручную
(валидация — ADR-028).
