# ADR-026: Базовые типы и конфигурация — UUID v4 в Go, деньги `decimal`, конфиг из env

## Статус
Принято

## Контекст
Мелкие сквозные решения, которые затрагивают все сервисы: где
генерируются идентификаторы, как представлены деньги на всех уровнях
(Postgres → Go → JSON → клиент), как читается конфигурация (ADR-011).

## Решение
**UUID (P-07):** `google/uuid`, v4, генерация в Go; `DEFAULT
gen_random_uuid()` в схеме — страховка. Override `uuid` → `uuid.UUID` в
`sqlc.yaml`. Id нужен до записи: имя файла фото, payload outbox.

**Деньги (P-08):** `shopspring/decimal`; Postgres `numeric(12,2)`; в JSON
— **строкой** (`"1500.50"`).
- Адаптер `pgx-shopspring-decimal` регистрируется на каждом соединении
  пула (`AfterConnect`).
- Overrides в sqlc для `numeric` и nullable-`numeric`
  (`decimal.NullDecimal`).
- Сравнение только через `Equal`/`Cmp`, не `==`; значения неизменяемы.
- Контракт «деньги строкой» обязателен для всех трёх клиентов.
- `float64` для денег не используется никогда.

**Конфигурация (P-12):** `os.LookupEnv` + своя структура конфига, без
библиотек. Все обязательные переменные проверяются при старте, ошибки
собираются через `errors.Join`; типы разбираются в одном месте
(`time.ParseDuration`, `strconv`); конфиг передаётся явно; секреты не
логируются. `godotenv` не нужен — compose сам подставляет `.env`.

## Альтернативы, которые рассматривались
- **UUID в БД (`gen_random_uuid()`)** — id нужен до вставки. Отклонено.
- **Деньги целыми копейками (`int64`)** — проще, но конвертация на
  границах и расхождение с моделью (`decimal` на диаграмме классов).
- **`caarlos0/env`, `viper`** — лишняя зависимость ради чтения env.

## Последствия
**Плюсы:** переход на UUID v7 — замена одного вызова; суммы читаемы в
БД; конфиг падает сразу и целиком, а не на первом обращении.

**Минусы:** адаптер decimal и overrides — обязательная обвязка в каждом
сервисе с деньгами.
