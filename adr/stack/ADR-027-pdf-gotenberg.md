# ADR-027: PDF справки — Gotenberg (HTML → PDF), `chassis/certificate` — HTTP-адаптер

## Статус
Принято

## Контекст
Справка — PDF из снапшота данных заказа (`sequence-certificate`).
Контракт `chassis/certificate`: «шаблон + данные → PDF», без знания
маппинга (TODO §5). Нужна кириллица. Зрелых PDF-библиотек на чистом Go с
удобной вёрсткой нет; встраивать headless Chrome в образ сервиса тяжело.

## Решение
- **Gotenberg** отдельным контейнером во внутренней сети, без публикации
  порта (ADR-010); тег мажорной версии; healthcheck `GET /health`.
- **`chassis/certificate`** — HTTP-адаптер к Gotenberg:
  `POST /forms/chromium/convert/html`, multipart, поле `files`, главный
  файл обязательно называется `index.html`. Шрифт с кириллицей (TTF,
  встроен через `go:embed`) уходит в том же запросе и подключается в
  `@font-face` **по имени файла** — без подкаталогов и абсолютных путей
  (Gotenberg кладёт файлы плоско).
- **Шаблон** — `html/template`, парсится один раз при старте (`go:embed`).
- `http.Client` с таймаутом.
- Сбой Gotenberg → попытка неудачна → повтор по ADR-035.
- В тестах Orders мокается интерфейс генератора; шаблон проверяется
  отдельно (рендер HTML без PDF).

Точная сигнатура интерфейса генератора по-прежнему откладывается до
написания кода (TODO §5).

## Альтернативы, которые рассматривались
- **Прямое рисование (`fpdf`-форки, `maroto`)** — вёрстка кодом,
  регистрация шрифта вручную, сложный шаблон. Отклонено.
- **`chromedp` в образе Orders** — тяжёлый образ, браузер внутри
  сервиса. Отклонено.
- **Коммерческие библиотеки** — лицензионные ограничения.

## Последствия
**Плюсы:** вёрстка на HTML/CSS; ноль PDF-зависимостей в Go; Orders
остаётся лёгким.

**Минусы:** ещё один контейнер; сетевой вызов, который может упасть
(покрыт повторами ADR-035).
