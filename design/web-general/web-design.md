# web-design

> Обновлено 30.10.2026: состояния оплаты (ADR-030), справки `pending`
> (ADR-035), ошибки регистрации и добавления ТС, фото ≤ 3 МБ, ошибки по
> `code`. В HTML добавлены отсутствовавшие кнопка "Оплатить" и плитка
> "Добавить ТС".

Наметки экранов веб-сайта (директор + клиент). Структурный каркас, не
финальный визуальный дизайн — опора для последующей отрисовки.

## Область применения

Единый веб-сайт с общей авторизацией, дальше — разные интерфейсы по
роли (директор / клиент). React Native (инженеры) — отдельно, не
описан здесь.

## Регистрация и роли

- Регистрация публична только для веба (в React Native — только вход,
  без публичной регистрации).
- Гостевой режим недоступен — запись на сервис требует регистрации.
- Форма регистрации не предлагает выбор роли. Новый пользователь
  всегда создаётся с ролью `client`. Роли — `client / engineer /
  director`; инженеры и директор заводятся вручную, напрямую в БД,
  администратором — отдельный админ-интерфейс не создаётся. Gateway
  проверяет роль по эндпоинтам (ADR-019): в RN-API пускается только
  `engineer`, в директорские — только `director`.

## Навигация директора

Несколько верхнеуровневых пунктов, внутри части из них — dropdown с
подразделами (не плоский список из 8 пунктов):

```
Дашборд · Заказы (Все заказы / Ожидают оплаты) ·
Каталог (Товары (склад) / Услуги)
```

> v1: пунктов «Отчёты» и «Чат» нет — они в v2.

## Навигация клиента

```
Мои заказы · Справки
```

Отдельного пункта "Мои ТС" нет — список машин показан прямо на
странице "Мои заказы" (объединено, чтобы не дублировать вход к одному
и тому же списку).

## Экраны

### 1. Регистрация
Поля: имя, телефон, пароль (от 8 до 72 символов — лимит bcrypt, ADR-023).
Кнопка "Создать аккаунт". Ссылка "Уже есть аккаунт? Войти".
Телефон уже зарегистрирован (`409 phone_taken`, телефон уникален среди
неудалённых пользователей, ADR-033) → ошибка под полем "Этот телефон уже
зарегистрирован. Войти?".

### 2. Дашборд клиента ("Мои заказы")
Сервисы: Orders (заказы), Vehicle (список ТС).
- Профиль клиента сверху (аватар-инициалы, имя, дата регистрации).
- **История заказов** — единый список, не разделённый на
  активные/завершённые табами: активные заказы визуально выделены
  (полная непрозрачность), завершённые — приглушены
  (`opacity: 0.85`), сортировка от новых к старым.
- **Мои ТС** — сетка карточек машин (`vehicles.owner_id = client`),
  каждая кликабельна → карточка конкретного ТС. Последняя ячейка —
  кнопка "Добавить ТС" (номер, марка, VIN; см. `sequence-add-vehicle`).
  Номер уже есть в системе (`409 plate_taken`) → "Этот номер уже
  зарегистрирован в СТО — обратитесь к мастеру".
  Без хотя бы одного ТС записаться на сервис нельзя — ТС выбирается в
  модалке записи.
- **Оплата** — только здесь, в вебе: у заказа в статусе `active` кнопка
  "Оплатить" (сага оплаты). В приложении инженера кнопки оплаты нет.
  Состояния (ADR-030, макет 3b):
  1. "Оплатить" — заказ `active`;
  2. после нажатия сервер отвечает `202 Accepted` → "Оплата
     подтверждается…", страница перечитывает статус заказа (до ~10 с);
  3. заказ остался `paid` и оплата подтверждена → бейдж "оплачен";
  4. заказ вернулся в `active` (склад не подтвердил товары или истёк
     дедлайн) → баннер "Оплата не прошла…" и снова кнопка "Оплатить".
     Автоматического повтора нет (ADR-016).

### 3. Карточка ТС (клиентский вид)
Сервис: Vehicle.
- Данные ТС (марка, номер, VIN). Статуса у ТС нет — этап работ
  ("принят / в работе / готов / выдан") показывается у текущего заказа.
- **Фото ТС (обложка)** — отдельное поле в Vehicle (`cover_photo_url`
  по смыслу), не то же самое, что фотофиксация. Одно изображение,
  заменяемое клиентом. Иконка камеры в углу превью + кнопка "Заменить
  фото". Перед отправкой фото уменьшается в браузере (canvas) до
  JPEG ≤ 3 МБ (ADR-029).
- Блок "Фотофиксация" — та же рабочая галерея, что видит инженер, но
  **без кнопки добавления** (клиент только просматривает).
- История работ — кликабельные строки → детали завершённого заказа.
- Переход "Назад" — на дашборд (не отдельно "к заказам", единая
  точка входа что для заказов, что для ТС).

### 4. Справки (список)
Сервис: Orders (certificate). Справка создаётся автоматически при
подтверждении оплаты (ADR-035), статусы `pending → completed / failed`.
- `completed` — зелёная иконка документа, кнопка скачивания.
- `pending` — "формируется…", без скачивания (обычно секунды).
- `failed` после 3 попыток — приглушённая карточка, красная
  иконка-предупреждение, без скачивания, текст "Обратитесь в поддержку"
  со статическими контактами СТО (TODO §6 п.3).

### Ошибки API (сквозное)
Конверт `{"error": {"code", "message", "fields"}}` (ADR-032). Тексты для
клиента — по `code`; `fields` — под полями формы; сеть / 502 / 504 —
общее "Сервис временно недоступен, попробуйте позже".

Зафиксированы как открытые попапы поверх содержимого страницы

- **Каталог** открыт → "Товары (склад)" / "Услуги"
