### Ревью заявки на сервис

- **Линтер.** В `orders/internal/order/booking.go` использовать
  `body.Date.IsZero()`. Тип OpenAPI уже встраивает `time.Time`.
- **Ошибки декодирования.** Разбирать ошибку `AsCreateServiceBookingRequest`
  до обработки полей. Сейчас ошибка может попасть в ответ как
  `validation_failed` с неполным или пустым `fields`.
- **Проверка взаимодействия.** Через nginx ещё нужно пройти заявку для
  своего и чужого ТС, форму чужой роли, прямое создание инженером и
  недоступность Vehicle. Отдельно убедиться, что Gateway отклоняет
  внешний запрос к внутреннему маршруту проверки владельца.

Gateway проверяет роль, Orders использует идентичность из `chassis/httpx`,
HTTP-вызов в Vehicle идёт до вставки. Репозиторий Orders отвечает за SQL,
Vehicle — за принадлежность ТС. Второго разбора доверенных заголовков нет.

## Находки ревью

1. `vehicle/internal/handler.go`: Vehicle повторяет проверку списка
   разрешённых ролей, которую уже делает Gateway. По ADR-019 проверка
   ролей маршрута принадлежит Gateway. Vehicle использует роль из доверенной
   идентичности для проверки владельца карточки клиента.
2. Разбор идентичности дублируется в Vehicle и Orders. Вынести в
   `chassis/httpx` чтение и проверку общих заголовков, включая UUID и роль.
   Подключить оба сервиса через общий код, сохранив поведение и журналирование
   Orders. Это следует правилу AGENTS.md об общей HTTP-обвязке.
3. `CreateVehicle` совмещает подготовку данных, SQL и перевод ошибки PG
   в HTTP. Выделить в том же пакете чистую подготовку данных и работу
   с PostgreSQL. Хендлер переводит результаты сценария в HTTP. Для
   `GetVehicle` отделить обработку `pgx.ErrNoRows` от проверки владельца.
4. Ветка проверки пустых полей после нормализации формирует
   `validation_failed` без `fields` (ADR-041). Для этой ветки заполнить
   причины по полям. Общий долг валидатора уже записан в `TODO.md`.
5. Добавить табличный тест нормализации госномера (ADR-031). Минимум
   проверить регистр, пробелы и совпадение латиницы с кириллицей.

### Внесённые правки

- Orders и Vehicle используют общую идентичность из `chassis/httpx`. Роли
  маршрутов Vehicle проверяет Gateway, принадлежность карточек — сервисы.
- Users запускает миграции через `postgres.ConnectAndMigrate`. Три сервиса
  используют `postgres.IsConstraintViolation`. Чтение PDF перенесено
  за границу репозитория Orders.
- Валидатор и ошибки разбора strict-запроса возвращают `validation_failed`
  с `fields`. Коды Gateway совпадают с OpenAPI, Inventory явно обрабатывает
  `ignore` и `tombstone`.
- Разделены подготовка данных, SQL и HTTP в Vehicle. Добавлен табличный
  тест нормализации госномера.
