## Рамки

- **Время:** 7 вечеров × 2–4 ч ≈ **20 ч** Go-логики разработчика.
- **Цель недели:** сквозной сценарий оплаты через nginx → Gateway, в docker compose:
  регистрация клиента → инженер создаёт заказ → добавляет товары (цена фиксируется) →
  клиент оплачивает → сага списывает товар в Inventory → справка PDF скачивается.
  Плюс отказной путь: Inventory недоступен → дедлайн 10 с → заказ снова `active`.
- **Критерий готовности:** агентский smoke-скрипт (`scripts/e2e.sh`, curl) проходит оба пути.

Первый вертикальный срез — добавить ТС и прочитать его карточку через nginx и
Gateway. Подготовка агента включает OpenAPI, новые миграции, SQL, конфигурацию
генерации и Compose. Логику пишет разработчик, после каждого сценария — ревью.

Итоговая проверка этапа через nginx — клиент добавляет ТС и создаёт заявку,
инженер берёт её в работу, добавляет товар и услугу, клиент оплачивает и
скачивает справку, инженер отмечает выдачу, директор находит заказ. Отдельно
проверяются отмена, недоступность источника для Gateway и регрессия дедлайна оплаты.

UI остаётся следующим этапом: веб клиента и директора, RN инженера по `design/`.
Chat и Reports остаются в `v2/`, интеграция платёжного шлюза — открытый вопрос
в `TODO.md` §3.

## Неделя 3 — технический долг

- [ ] **Ежемесячная очистка фото Vehicle.** Раз в месяц воркер сверяет файлы
  в томе Vehicle с ключами обложек и снимков галереи в PostgreSQL. Удаляет
  файлы без записи в БД и файлы, на которые ссылаются только записи с
  заполненным `deleted_at`. Файл с действующей ссылкой сохраняется.
  При замене обложки прежний файл остаётся в томе до такого прогона.
  Очистка учитывает порядок загрузки «файл → запись в БД», чтобы параллельная
  загрузка успела сохранить ключ. Проверка включает старую обложку, файл
  удалённой записи, действующий снимок и загрузку во время прогона.
