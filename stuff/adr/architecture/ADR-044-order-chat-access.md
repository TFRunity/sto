# ADR-044. Доступ к чату по заказу

## Статус

Принято для v3. [ADR-020](ADR-020-responsible-engineer-and-executors.md)
определяет ответственного инженера, [ADR-018](../../v2/adr/architecture/ADR-018-chat-websocket-exception.md) — транспорт доставки.

## Решение

Клиент открывает диалог через `POST /chat/dialogs/order`, передавая `order_id`.
Gateway передаёт доверенные идентификатор и роль пользователя. Chat читает
`client_id` и текущий `engineer_id` из Orders через
`GET /internal/orders/{id}/chat-participants`. Внутренний маршрут доступен
в сети сервисов. Chat сверяет роль и владельца, а при отсутствии ответственного
возвращает `409 order_engineer_not_assigned`.

Chat хранит диалоги по заказу с уникальной тройкой
`(order_id, client_id, engineer_id)`. Повторное открытие той же тройки
возвращает существующий диалог. Сообщения остаются в исходном диалоге
при смене назначения.

| Пользователь | Инженер диалога совпадает с текущим ответственным | Другой ответственный или назначение снято |
| --- | --- | --- |
| Владелец заказа, участвующий в диалоге | Список, история, отправка, отметка прочтения, события | Список и история в режиме чтения |
| Инженер, участвующий в диалоге | Список, история, отправка, отметка прочтения, события | Доступ закрыт |
| Другие пользователи | Доступ закрыт | Доступ закрыт |

Новый ответственный получает отдельный диалог с клиентом, когда клиент
открывает чат по заказу. Если повторно назначен инженер, у которого уже
есть диалог с этим клиентом по этому заказу, прежний диалог снова доступен
обоим для переписки.

Gateway проверяет JWT при открытии `GET /api/chat/events` и завершает туннель
по истечении токена. Соединение привязано к пользователю. Chat сверяет
актуальное назначение при каждой HTTP-операции с диалогом и перед доставкой
каждого WebSocket-события об этом диалоге. При недоступности Orders Chat не
выдаёт данные и не доставляет события, для которых не удалось проверить доступ.

Событие `message` или `read` содержит идентификатор диалога. После события
клиент обновляет данные по HTTP. При новом подключении он перечитывает
список диалогов, открытый диалог и число непрочитанных сообщений.
