# ADR-045. Push-уведомления в приложении инженера

## Статус

Выбрано для v3. Контракт и реализация отслеживаются в [вечере 5](../../tasks/v3/evening-5.md).

## Провайдер и регистрация

Expo SDK 56 использует `expo-notifications`. Устройство получает Expo Push Token,
Expo Push Service передаёт уведомление в FCM v1. Для Android нужны
`google-services.json` приложения `ru.sto.engineer`, ID проекта EAS,
учётные данные FCM v1 в Expo и отдельная Android-сборка.
[Настройка Expo](https://docs.expo.dev/push-notifications/push-notifications-setup/) ·
[Учётные данные FCM v1](https://docs.expo.dev/push-notifications/fcm-credentials/)

Android создаёт канал `sto`, запрашивает системное разрешение и после входа
передаёт токен через `PUT /me/push-device`. После возврата приложения на передний
план регистрацию можно повторить. При явном выходе приложение вызывает
`POST /me/push-device/revoke` с токеном, пока JWT ещё доступен. Users получает
владельца из доверенного заголовка Gateway. У токена один владелец, повтор
регистрации переносит его к текущему инженеру, отзыв ограничен текущим владельцем.
Токены передаются в теле защищённых запросов и исключены из логов.

## События и выбор получателей

Orders сохраняет `BookingRequested {order_id}` в той же транзакции, что и
новую заявку клиента со статусом `requested`. Перед доставкой уведомления
проверяется, что заявка открыта в пуле. Получатели — действующие инженеры.
Прямой приём не публикует это событие.

Chat сохраняет `ChatMessageCreated {dialog_id, message_id}` в той же
транзакции, что и сообщение. При обработке события Chat определяет собеседника
по сохранённым участникам, исключает автора и для заказа повторно сверяет
назначение с Orders по [ADR-044](ADR-044-order-chat-access.md). При недоступности
Orders обработку можно повторить. Действительно недоступный диалог или собеседник
другой роли завершают обработку без отправки.

Перед обращением к Expo Users выбирает токены живых инженеров с
`notifications_enabled = true`. Для чата выбор ограничен ID проверенного
собеседника. Диалог и сообщение читаются по защищённому API.

Тело уведомления одинаково для обоих событий: «Откройте приложение, чтобы
посмотреть обновление». Заголовок — «СТО». Поле `data` содержит один из вариантов:

| Событие | `data` | Экран после тапа |
| --- | --- | --- |
| `BookingRequested` | `{kind: "booking_requested", order_id: UUID}` | Строка заявки из `GET /orders?status=requested` |
| `ChatMessageCreated` | `{kind: "chat_message", dialog_id: UUID}` | Диалог после чтения списка и истории, защищённых по ADR-044 |

Если заявка уже ушла из пула или права на диалог изменились, Android показывает
недоступность. Ответ 401 ведёт на вход. Текст сообщений, имена и сведения о
машине остаются в приложении.

## Гарантии отправки

Outbox и RabbitMQ работают с повторной доставкой. Для фонового отправителя
бизнес-ключ — событие и токен. Успешный push ticket сохраняется, чтобы повтор
команды не отправлял уже принятый Expo токен повторно. При обрыве между приёмом
Expo и записью ticket возможен повтор. Receipt описывает передачу в FCM.
Ошибка `DeviceNotRegistered` в ticket или receipt удаляет регистрацию, если
она не обновилась после отправки.
[Протокол Expo Push Service](https://docs.expo.dev/push-notifications/sending-notifications/)
