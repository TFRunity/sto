# Генерация SQL и HTTP-кода

Из корня репозитория для третьего вечера:

```sh
make generate MODULE="orders inventory"
```

`generate` — цель [Makefile](../../Makefile). `MODULE` задаёт список каталогов.
Кавычки передают два имени одним аргументом shell. Без `MODULE` Make перебирает
все модули, включая Users. В записи `make generate=` слово с `=` — присваивание
пустой переменной. Цель тогда выбирается по умолчанию, и сейчас это тоже `generate`.

## Что происходит

Make перебирает выбранные модули в заданном порядке. В каждом он сначала
запускает sqlc при наличии `sqlc.yaml`, затем oapi-codegen при наличии
`oapi-codegen.yaml`. Перед каждым запуском он печатает имя инструмента и модуля.

| Инструмент | Вход | Выход |
| --- | --- | --- |
| sqlc | `sqlc.yaml`, схема из `migrations/*.sql`, запросы из `queries/*.sql` | `internal/db/` с типами и методами запросов |
| oapi-codegen | `oapi-codegen.yaml`, общий `api/openapi.yaml`, тег сервиса из конфига | `internal/api/api.gen.go` с DTO, интерфейсом strict-сервера и HTTP-обвязкой |

Оба генератора запускаются через `go run` с версиями из Makefile. Первый запуск
может скачать зависимости инструментов и заполнить кэши Go. Генераторы пишут Go-файлы
в рабочее дерево. Для этой настройки подключение к БД, применение миграций и Docker
не требуются.

## Как менять SQL

1. Если нужна новая колонка или таблица, добавь новую миграцию. Правило для
   применённых миграций описано в [ADR-024](../stack/ADR-024-db-access-sqlc-pgx-goose.md).
2. Добавь или измени запрос в `queries/`. Первая строка задаёт имя Go-метода
   и вид результата. Например, `-- name: GetItem :one` возвращает одну запись
   или ошибку, `:many` возвращает список, `:exec` возвращает ошибку выполнения,
   `:execrows` возвращает ещё и число затронутых строк.
3. Запусти генерацию и посмотри сигнатуры методов в `internal/db`. Исправления
   делай в SQL или конфиге и генерируй снова.

Для HTTP меняй `api/openapi.yaml`. Тег операции определяет, в какой сервис
она попадёт, а `operationId` участвует в выборе имени метода. В одном контракте
могут поменяться сразу несколько сервисов. Запусти генерацию для всех затронутых
модулей и проверь, что реализации хендлеров соответствуют новым интерфейсам.

## Как локализовать сбой

1. Найди последнюю строку вида `sqlc: orders` или `oapi-codegen: inventory`.
   Make останавливается на первой ошибке. Файлы, записанные на предыдущих шагах,
   остаются на диске.
2. Повтори генерацию для одного модуля, например `make generate MODULE=orders`.
   Если нужен только один инструмент, из корня можно запустить его отдельно.
   Сверь версию с Makefile.

   ```sh
   (cd orders && go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.29.0 generate)
   (cd orders && go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@v2.5.0 -config oapi-codegen.yaml ../api/openapi.yaml)
   ```

3. Смотри первую содержательную ошибку перед итоговым сообщением Make.

   | Симптом | Где смотреть |
   | --- | --- |
   | sqlc сообщает `column ... does not exist` | Сверь запрос с миграциями в каталоге `schema` из `sqlc.yaml`. Колонка в живой БД сама по себе генератору не видна. |
   | sqlc выдал неожиданный тип Go | Проверь тип и nullable колонки, затем `overrides` в `sqlc.yaml`. Для `NOT NULL` и nullable могут понадобиться отдельные overrides. |
   | oapi-codegen жалуется на `$ref` | Проверь путь к компоненту в OpenAPI. Если генерация проходит, но метода нет, проверь тег операции и `include-tags`. |
   | Ошибка скачивания или выбора Go toolchain | Проверь версию Go, настройки прокси модулей и доступ к сети. |
   | Ошибка сборки sqlc с упоминанием C-компилятора | Проверь `go env CGO_ENABLED` и `gcc --version`. В шапке Makefile есть вариант запуска sqlc через Docker. |
   | Генерация прошла, а сборка жалуется на импорт | Проверь зависимости модуля. Порядок работы описан в [командах Go](go.md#go-mod-tidy). |

4. Посмотри `git status --short` и `git diff -- orders inventory`. Новые
   неотслеживаемые файлы видны в статусе и открываются отдельно. Когда код сервиса
   и зависимости готовы, проверь сборку и тесты нужного модуля.
