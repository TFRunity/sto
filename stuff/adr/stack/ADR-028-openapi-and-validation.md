# ADR-028: Контракт API — OpenAPI spec-first + `oapi-codegen`; валидация входа — вручную

## Статус
Принято. Раздел «Валидация входа» частично заменён ADR-041 (02.11.2026): структура
запроса проверяется по спецификации, `Validate()` — только для правил вне неё.

## Контекст
Три клиента (две веб-части, RN) и шесть сервисов. Без машиночитаемого
контракта расхождения между клиентами и сервисами ловятся только в
рантайме. Отдельно — как валидировать вход (ADR не требуют библиотеку).

## Решение
**Контракт (P-16):** spec-first OpenAPI 3.0.x + `oapi-codegen` v2
(`std-http-server`, strict-режим).
- Одна публичная спецификация; сервисы генерируют серверы из своей части
  (по тегам); Gateway — только для собственных эндпоинтов (дашборд).
- Префиксы путей согласуются с переписыванием путей в Gateway.
- `x-go-type` для денег (ADR-026), `format: uuid` → `google/uuid`.
- Формат ошибок описывается в спецификации как общий компонент (ADR-032).
- Рантайм-зависимость `oapi-codegen/runtime`.
- Сгенерированный код коммитится, CI проверяет дифф (ADR-014).
- TS-типы для React/RN генерируются из той же спецификации.
- Валидация проксируемых запросов по спецификации в Gateway — возможное
  расширение, не сейчас.

**Валидация входа (P-13):** вручную — метод `Validate()` у входных DTO;
общие хелперы проверок и тип ошибки валидации «поле → причина» в
`chassis`. `DisallowUnknownFields`. Поля идентичности (`owner_id`,
`client_id` клиента, роль) из тела не принимаются — берутся из заголовков
Gateway (ADR-037). Доменные правила живут отдельно (ADR-031).

## Альтернативы, которые рассматривались
- **Code-first (`swaggo/swag`)** — спецификация вторична, клиенты узнают
  об изменении постфактум. Отклонено.
- **Без контракта** — отклонено по причине выше.
- **`go-playground/validator`** — теги вместо кода, условная логика
  неудобна. Отклонено.

## Последствия
**Плюсы:** контракт проверяет компилятор у всех сторон; единый формат
ошибок валидации.

**Минусы:** три слоя типов (OpenAPI DTO, sqlc, домен) с маппингом;
генерация как обязательный шаг (`make generate`).
