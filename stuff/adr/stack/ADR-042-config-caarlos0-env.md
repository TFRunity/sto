# ADR-042: Конфигурация — `caarlos0/env` на тегах структуры

## Статус
Принято. Частично заменяет ADR-026 (раздел «Конфигурация», P-12). UUID и деньги из
ADR-026 остаются в силе.

## Контекст
ADR-026 выбрал `os.LookupEnv` + своя структура без библиотек: «лишняя зависимость ради
чтения env». На практике это шаблонный код на каждую переменную (поиск, проверка
обязательности, разбор типа, сбор ошибки) в каждом из шести сервисов. Разработчик
предпочитает декларативные готовые решения самописной обвязке (`CLAUDE.local.md`).

## Решение
- **`github.com/caarlos0/env/v11`**, версия `v11.4.1` (последняя на 02.11.2026; v12 нет):
  конфиг каждого сервиса — структура с тегами `env:"NAME,required"` (или `notEmpty`),
  `envDefault:"…"`. Generic API: `ParseAs[T any]() (T, error)`,
  `ParseAsWithOptions[T any](opts Options) (T, error)`; ошибки собираются в
  `AggregateError` (с v11.3.0 — `Unwrap() []error`, совместим с `errors.Is/As`).
  `time.Duration` поддерживается из коробки (сверено с pkg.go.dev).
- Требования P-12 сохраняются, меняется только способ:
  - все обязательные переменные проверяются при старте, ошибки — **все сразу**
    (библиотека собирает их в одну ошибку);
  - типы (`time.Duration`, числа) разбираются библиотекой в одном месте;
  - конфиг передаётся явно, глобального состояния нет;
  - секреты не логируются;
  - `godotenv` не нужен — переменные приходят из compose или `make run` (ADR-040).
- Структура конфига — у каждого сервиса своя; в `chassis/config` — только общее
  (обёртка разбора, `LOG_LEVEL` → `slog.Level`).

## Альтернативы, которые рассматривались
- **stdlib (`os.LookupEnv` + `errors.Join`)** — решение ADR-026; ноль зависимостей, но
  шаблонный код на каждое поле в каждом сервисе. Заменено.
- **`viper`** — файлы, флаги, горячая перезагрузка; для env-only избыточен. Отклонено.

## Последствия
**Плюсы:** конфиг читается из одного объявления структуры; `required` и значения по
умолчанию — декларативно; одинаково во всех сервисах.

**Минусы:** зависимость в `chassis` и сервисах; имена переменных — строки в тегах, опечатку
компилятор не поймает (её поймает проверка `required` при старте — для обязательных).
