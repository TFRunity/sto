Наметки экранов веб-сайта для роли директора. Часть общего веб-сайта
(регистрация, роли, общая структура — см. general-web-design.md).
Структурный каркас, не финальный визуальный дизайн.

## Навигация

Несколько верхнеуровневых пунктов, часть — с dropdown-подразделами:

```
Дашборд · Заказы (Все заказы / Ожидают оплаты) ·
Каталог (Товары (склад) / Услуги)
```

> v1: пунктов «Отчёты» (Список отчётов / Сотрудники) и «Чат» нет — они в v2
> (`v2/design/web-director/director-web-design-v2.md`).

## Экраны

### 1. Дашборд
Сервисы: Orders (метрики и последние заказы), Users (загрузка
инженеров) — как на `sequence-director-dashboard` (API composition в
Gateway). В v1 «выручка сегодня» = сумма `paid`-заказов за день: модуля
Reports нет, платёжный модуль не спроектирован (TODO §4).
- Четыре метрик-карточки: выручка сегодня, заказов сегодня, в работе,
  ожидают оплаты (выделено красным — требует внимания).
  «Ожидают оплаты» = `status = active` + этап работ `готов` (см.
  ADR-021); отдельного статуса заказа для этого нет.
- Двухколоночный блок: "Последние заказы" (со статус-бейджами) слева,
  "Загрузка инженеров" (число заказов на сотрудника) справа.
- Ошибка — **всё или ничего** (ADR-032): если Orders или Users не ответил
  (502) или не уложился в 3 с (504), дашборд не показывается целиком —
  экран "Не удалось загрузить дашборд" с кнопкой "Повторить" (макет 1b).

### 2. Все заказы (табличный вид)
Сервис: Orders.
Табличный формат (не карточки, в отличие от клиента/инженера) —
директору важна плотность и сравнение заказов между собой.
Колонки: ТС/номер, клиент, инженер (ответственный), сумма, статус,
этап работ.
Фильтры (Все / В работе / Ожидают оплаты / Оплачены / Отменены) +
поиск по номеру/клиенту. «В работе» = `active`, «Ожидают оплаты» =
`active` + этап `готов`, «Оплачены» = `paid`, «Отменены» = `cancelled`.
Этап «выдан» виден отдельной колонкой, не фильтром статуса (в макете
раньше «выдан» стоял в колонке «Статус» — исправлено).

Поиск (ADR-039, `sequence-director-orders`): эндпоинт Gateway
`GET /director/orders` — строка поиска превращается в id через Users
(имя, телефон) и Vehicle (госномер), Orders фильтрует и пагинирует.
- от 2 символов, по подстроке; удалённые клиенты тоже находятся;
- больше 200 совпадений в Users или Vehicle → `422 search_too_broad` —
  "Слишком много совпадений, уточните запрос" (макет 2b);
- отказ любого сервиса → 502 / 504, как у дашборда.

### 5. Управление каталогом (два таба)
Сервисы: Inventory (Товары/склад), Services (Услуги) — раздельные
таблицы, отражающие разделение сервисов в бэкенде.
- **Товары (склад)**: таблица — название, цена, остаток, редактирование,
  удаление. Низкий остаток выделяется красным (сигнал пополнить склад).
- **Удаление** — soft delete (ADR-033): товар/услуга пропадает из каталога и
  выбора у инженера, старые заказы сохраняют позицию.
- **Цена** — изменение не трогает прошлые заказы: цена фиксируется в
  позиции заказа при добавлении (ADR-034).
- **Услуги**: та же структура таблицы, без колонки "Остаток" — у
  Services нет складского учёта.
- Кнопка "Добавить товар"/"Добавить услугу" меняется по активному табу.

### 6. Детали заказа (директорский просмотр)
Сервис: Orders + Vehicle + Inventory + Services (агрегация). Полностью
read-only — открывается по клику из "Все заказы".
- Шапка: номер заказа, статус-бейдж и этап работ. Статусы заказа
  (решение 08.10.2026, ADR-021): `requested` ("заявка"), `active`
  ("в работе"), `paid` ("оплачен" — финальный), `cancelled`
  ("отменён"). Статуса `completed` нет. "Готов"/"выдан" — это этап
  работ (`принят / в_работе / готов / выдан`), отдельная ось от
  статуса; "выдан" возможен только при `paid` и подтверждённой оплате.
  В макете бейдж был "выполнен" (такого статуса нет) — исправлено на
  "оплачен" + "этап: выдан".
- Блок ТС + клиент — данные, ссылка-переход на карточку ТС и на
  сотрудника-клиента, без полей редактирования.
- Блок "Товары" (Inventory) и блок "Услуги" (Services) — списком,
  без кнопок добавления/удаления.
- Блок "Инженеры" (`order_engineers`).
- Итоговая сумма.
- Единственное интерактивное действие — ссылка "Открыть справку",
  видна только у справки `completed`; при `pending` — "Справка
  формируется…", при `failed` после 3 попыток — "Не сформирована".
  Справка создаётся автоматически при подтверждении оплаты (ADR-035).
  Кнопки "Оплатить" нет: это действие клиента.

### 8. Настройки профиля директора
Сервис: Users.
- Аватар-инициалы, имя, роль "Директор", дата начала работы.
- Телефон — только отображение (как и в профиле инженера, RN).
- Переключатель уведомлений.
- Кнопка "Выйти" (`text-danger`).
- Без пункта "Поддержка" — это сценарий retry-справки, актуален для
  клиента, не для директора. Без геолокации — по той же причине, что и
  в RN-профиле: не относится к сценариям приложения.
