# Фронтенд · Вечер 1 — Каркас веба и контракт API

**Итог вечера:** Next.js запускается, у двух кабинетов свои маршруты и общие UI-компоненты. Типы API воспроизводимо генерируются из OpenAPI.

Задачи идут по порядку. После каждой сверяем результат с проверкой.

## [x] 1. Каркас Next.js

Создать `frontend/web/` с App Router и TypeScript. Выделить `app/`, `features/` и `lib/api/`. Добавить layout’ы `/customer` и `/director`.

**Проверка:** Оба маршрута открываются напрямую и при переходе по ссылке.

Проверено через локальный HTTP: главная и оба кабинета отвечают `200`, ссылки
на оба кабинета присутствуют на всех трёх страницах. Проверка TypeScript прошла.

---

## [ ] 2. Стили и общие компоненты

Подключить Tailwind CSS и shadcn/ui. Задать общие цвета и типографику по макетам. Подготовить кнопку, поле, диалог и таблицу.

**Проверка:** На узком и широком экранах работают фокус с клавиатуры, поля и диалог.

Tailwind CSS и четыре компонента shadcn/ui подключены. Сборка Webpack выпускает CSS
с цветами макетов. Проверка фокуса и диалога в браузере остаётся открытой.

---

## [x] 3. Контракт и запросы

Настроить генерацию TypeScript-типов из `api/openapi.yaml` и клиент Gateway в `lib/api/`. Подключить TanStack Query и типизированный разбор конверта `error`.

**Проверка:** Повторная генерация даёт тот же результат. Статус HTTP и `error.code` доступны вызывающему коду.

Команда из корня STO — `make generate-frontend-api`.
Она обновляет общий для двух клиентов файл `frontend/common/api/schema.d.ts`. Повторная
генерация дала идентичный файл. На подменённых ответах проверены успешный
запрос, ошибка валидации с `status`, `code` и `fields` и HTML-ответ nginx с HTTP 502.
