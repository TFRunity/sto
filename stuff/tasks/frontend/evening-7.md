# Фронтенд · Вечер 7 — Сквозная приёмка

**Итог вечера:** Один заказ проходит через веб клиента, React Native инженера и веб директора через nginx и Gateway.

Задачи идут по порядку. После каждой сверяем результат с проверкой.

## [ ] 1. Режим запуска

Согласовать режим сборки и развёртывания веба с ADR-038. Подключить веб к `make up`: nginx обслуживает интерфейс по `/` и направляет `/api/` в Gateway. Описать локальный запуск через `make web` и запуск мобилки с тестовым Gateway.

**Проверка:** После `make up` интерфейс и API доступны через nginx на одном origin. Мобильное приложение достигает Gateway с устройства или эмулятора.

Веб добавлен в Compose как Next.js standalone. nginx направляет `/` в
Next.js, а `/api/` в Gateway. Локальный `make web` использует порт 3001,
поскольку порт 3000 на хосте опубликован для Gotenberg.
После `make up SVC=nginx` и перечитывания конфигурации работающего nginx
проверены перенаправление на вход, HTML статического и динамического маршрутов,
CSS и ответ API 401 без сессии на одном origin. Проверка с Android открыта.
После переноса конфигурации в образ `make up SVC=nginx` собрал и запустил
новый nginx. Перенаправление, HTML, CSS и ответ Gateway 401 подтверждены
без ручного перечитывания конфигурации.

## [ ] 2. Сквозной сценарий

Пройти цепочку: регистрация, ТС, заявка, claim, позиции и фото, оплата, PDF, выдача, поиск директором.

**Проверка:** На всех экранах совпадают ID заказа, сумма и итоговый этап.

На локальном nginx веб перенаправляет на вход. Повторный `bash scripts/e2e.sh`
подтвердил оплату, PDF, обработку дубликата и возврат заказа и остатка по дедлайну.
Inventory снова запущен скриптом. Подключение Android и полный прогон через
интерфейсы трёх ролей остаются открытыми.

---

## [ ] 3. Ошибки и адаптивность

Проверить истёкшую сессию, отказ в доступе, недоступный API, повтор чтения, пустую выдачу и узкий экран. Сверить расхождения с макетами и текущим API.

**Проверка:** Для ошибок есть понятный выход или повтор. Основные действия доступны с клавиатуры в вебе.
