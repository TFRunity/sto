# СТО v3 — задачи на семь вечеров

Объём описан в [плане v3](../../v3/PLAN.md). Вечера идут в порядке зависимостей. Отметка оплаты задаёт дату для отчёта по выручке, экран справок получает переход в поддержку после подключения Chat, а Reports использует доставку, подготовленную на пятом вечере.

| Вечер | Состояние |
| --- | --- |
| [1. Отметка оплаты, списание и выдача](evening-1.md) | Реализация готова. Записаны результаты проверок API и TypeScript. Открыт [приёмочный прогон](evening-1.md#приёмка-вечера-1) веба, Android и перехода на существующих данных v1. |
| [2. Заказы инженера и прямой приём](evening-2.md) | Реализация и целевой прогон API завершены. Go-тесты, линт и TypeScript прошли. Ручной Android перенесён на вечер 7. |
| [3. Детали директора, справки и профили](evening-3.md) | Go-тесты, линт, TypeScript и три целевых E2E-сценария через nginx прошли. Ручная приёмка интерфейсов открыта. |
| [4. Chat и поддержка](evening-4.md) | Chat, WebSocket и интерфейсы реализованы. Go-тесты, линт, TypeScript и целевые прогоны через nginx прошли. Открыта [ручная приёмка](evening-4.md#ручная-приёмка). |
| [5. Уведомления и доставка сообщений](evening-5.md) | Подготовлены регистрация и переходы на Android, схема API, SQL устройств и определения очередей Reports. Открыты серверная отправка push, супервизор RabbitMQ и приёмка. |
| [6. Reports и статистика сотрудников](evening-6.md) | Есть проектирование в v2. Сервис, отчёты и экран сотрудников открыты. |
| [7. CI, обработка отказов и сквозная приёмка](evening-7.md) | Есть тесты Go-модулей, скрипт проверки оплаты и веб за nginx. CI, оставшиеся проверки и итоговая приёмка открыты. |

Текущая приёмка — [интерфейсы вечера 3](evening-3.md#фронтенд). Открытые проверки [вечера 1](evening-1.md#приёмка-вечера-1) ведём отдельно. Для каждой задачи используем целевой e2e-режим и проверки затронутых сценариев. Полный набор запускаем на [общей приёмке](evening-7.md#сквозная-приёмка).

## Границы задач

| Раздел | Где работаем | За что отвечает |
| --- | --- | --- |
| Бэкенд | Go-сервисы, Gateway, `chassis`, SQL и `api/openapi.yaml` | Источники данных, бизнес-правила, права, переходы состояний, расчёты, формирование PDF и межсервисный обмен. Доменную логику размещаем в сервисе-владельце, композицию ответов — в Gateway. |
| Фронтенд | `frontend/web`, `frontend/mobile`, `frontend/common` | Экраны, навигация, формы, клиентская валидация, запросы к Gateway, кэш и отображение состояния сервера. Next.js и RN используют общий сгенерированный контракт. |
| Инфраструктура | Compose, nginx, RabbitMQ definitions и CI | Запуск, сетевые маршруты, TLS и проверки сборки. |
| Сквозная приёмка | Веб и Android через nginx и живой Gateway | Проверка цепочки целиком после подключения обеих сторон. |

Если экрану нужны новые данные или действие, сначала описываем серверную часть и контракт в разделе «Бэкенд». Экран вызывает Gateway. Правила доступа, подтверждение оплаты, готовность справки, списание и расчёты отчётов выполняются на сервере. Для задач, затрагивающих обе стороны, у каждой стороны свой чекбокс и своя проверка.

Отмечаем задачу после её проверки. Если реализация проверена по коду, тестам или TypeScript, а для приёмки нужен живой стенд, указываем выполненные проверки в задаче и оставляем чекбокс приёмки открытым. По мере изменения контрактов обновляем OpenAPI и генерируемые типы. Для новых сценариев добавляем sequence, изменения модели отражаем в диаграмме классов, изменения архитектурных решений фиксируем в ADR. [Правила проекта](../../../AGENTS.md)
