# СТО v3 · Вечер 2 — Заказы инженера и прямой приём

**Итог вечера.** Инженер открывает свои заказы и историю ТС, берёт заявку из пула или создаёт заказ при приёме клиента.

**Согласовано.** Клиент сам регистрируется в вебе. Инженер выбирает действующего клиента по имени или телефону и вручную вводит госномер. Ответственному доступна вся история ТС из его текущего заказа до выдачи. История включает заказы других инженеров и открывает их в Android в режиме просмотра. Оплаченный заказ остаётся в активных до выдачи. Отменённые и выданные заказы попадают в завершённые.

Обычную карточку читают ответственный и исполнители. Позиции, этап, отмену и повтор списания меняет ответственный. Повторное назначение активного заказа сохраняет поведение ADR-017. При открытии карточки из истории Orders повторно проверяет доступ по текущему заказу.

## Бэкенд

### [x] 1. Чтение заказов инженером

В Orders выдать активные и завершённые заказы через `GET /engineer/orders`, исполнителей через `GET /orders/{id}` и историю через `GET /orders/{id}/vehicle-history`. Gateway добавляет марку и госномер из Vehicle к строкам «Моих заказов». Право чтения истории и строку заказа проверять в одном снимке БД. Пул остаётся на `GET /orders?status=requested`. [ADR-020](../../adr/architecture/ADR-020-responsible-engineer-and-executors.md) · [Sequence чтения заказов](../../v3/uml/sequence-engineer-orders.drawio)

**Проверка.** API включает заказ в список ответственного, отдаёт состав исполнителей и применяет ограничения при чтении истории. Пул по-прежнему выдаёт заявки.

---

### [x] 2. API прямого приёма

Подобрать клиента через `GET /engineer/clients` и найти ТС по нормализованному госномеру через `GET /engineer/vehicles`. Для отсутствующей машины создать карточку с выбранным владельцем через `POST /engineer/vehicles`. При `POST /orders` Orders сверяет владельца машины с выбранным клиентом, создаёт активный заказ и назначает ответственного в одной транзакции по ADR-020. [Sequence создания заказа](../../uml/sequence/sequence-create-order.drawio)

**Проверка.** Сервер сохраняет выбранного владельца нового ТС, создаёт заказ в `active` и записывает ответственного в состав исполнителей. Повтор запроса с тем же ключом возвращает заказ. Если клиент или машина изменились, Orders возвращает конфликт.

## Фронтенд

### [x] 1. Реализация списков и деталей в RN

Подключить экраны «Мои заказы», активные и завершённые заказы, историю ТС и блок исполнителей. Оставить отдельный переход к пулу заявок. [План RN](../../design/frontend-plan.md#react-native-инженера)

**Проверка.** После claim заказ появляется в списке, завершённый заказ доступен в истории, а в деталях видны ответственный и остальные исполнители.

### [x] 2. Реализация формы прямого приёма в RN

Подключить поиск клиента, поиск и создание ТС к маршрутам Gateway. Отправить выбранные данные через `POST /orders`, открыть детали и при возврате перечитать список инженера.

**Проверка.** Инженер находит существующую пару или оформляет недостающую карточку. После отправки открывается заказ, который клиент видит в истории. При ошибке форма сохраняет введённые данные. Android записывает ключ до отправки заказа и повторно использует его для той же пары клиента и ТС после потери ответа.

Общая TypeScript-схема обновлена. Проверка TypeScript Android после правок ревью прошла. Для приёмки API используется `bash scripts/e2e.sh engineer-orders`. Режим проверяет прямой приём и повтор по ключу, взятие заявки из пула, оба списка, исполнителей, доступ к истории, выдачу, PDF и права на повтор списания. Ручной Android и полный прогон `bash scripts/e2e.sh` перенесены на [общую приёмку](evening-7.md).

После правок ревью обновлены артефакты Gateway, Orders, Users и Vehicle. Генерация Users и Vehicle завершена из локальных бинарников sqlc 1.29.0 и oapi-codegen 2.5.0. `make test lint` прошёл во всех семи Go-модулях, линтер везде показал `0 issues`.

Целевой `bash scripts/e2e.sh engineer-orders` прошёл через живой Gateway после пересборки стенда. Подтверждены взятие заявки, прямой приём и повтор по ключу, списки и права на историческую карточку, выдача, PDF и повтор списания.
