# СТО v3 · Вечер 2 — Заказы инженера и прямой приём

**Итог вечера.** Инженер открывает свои заказы и историю ТС, берёт заявку из пула или создаёт заказ при приёме клиента.

## Бэкенд

### [ ] 1. Чтение заказов инженером

В Orders описать выдачу активных и завершённых заказов по ответственному и всех исполнителей из `order_engineers` в деталях. Определить и реализовать проверку доступа к истории ТС. Сохранить отдельный пул заявок. [ADR-020](../../adr/architecture/ADR-020-responsible-engineer-and-executors.md)

**Проверка.** API включает заказ в список ответственного, отдаёт состав исполнителей и применяет ограничения при чтении истории. Пул по-прежнему выдаёт заявки.

---

### [ ] 2. API прямого приёма

Описать разрешённый инженеру поиск ТС в Vehicle и подбор клиента в Users через Gateway. Для отсутствующей машины предусмотреть создание карточки с выбранным владельцем. Согласовать и реализовать правила создания клиентского аккаунта инженером. Сверить существующий `POST /orders` с ADR-020. [Sequence создания заказа](../../uml/sequence/sequence-create-order.drawio) · [Полная use case diagram](../../v2/uml/use-case/use-case-diagram-v4-full.drawio)

**Проверка.** Сервер сохраняет владельца нового ТС, создаёт заказ в `active` и записывает ответственного в состав исполнителей.

## Фронтенд

### [ ] 1. Списки и детали в RN

Подключить экраны «Мои заказы», активные и завершённые заказы, историю ТС и блок исполнителей. Оставить отдельный переход к пулу заявок. [План RN](../../design/frontend-plan.md#react-native-инженера)

**Проверка.** После claim заказ появляется в списке, завершённый заказ доступен в истории, а в деталях видны ответственный и остальные исполнители.

### [ ] 2. Форма прямого приёма в RN

Подключить поиск, выбор и создание ТС и клиента к согласованным маршрутам. Согласовать способ сканирования госномера, добавить соответствующее действие и оставить ручной ввод. Отправить выбранные данные через `POST /orders`, открыть детали и обновить список инженера.

**Проверка.** Инженер находит существующую пару или оформляет недостающую карточку. После отправки открывается заказ, который клиент видит в истории. При ошибке форма сохраняет введённые данные.
