# СТО v3 · Вечер 3 — Детали директора, справки и профили

**Итог вечера.** Директор открывает полные детали заказа, клиент видит состояние справки, в кабинетах доступны данные профиля.

## Бэкенд

### [ ] 1. Статусы справок и доступ к PDF

В Orders добавить выдачу списка и статусов. Сервер различает запланированный повтор по `next_attempt_at` и окончательную ошибку после третьей попытки. Согласовать и реализовать права директора и инженера на статус и PDF. [ADR-035](../../adr/architecture/ADR-035-certificate-worker.md)

**Проверка.** API различает ожидание, готовность и окончательную ошибку. PDF скачивается только с согласованными правами.

---

### [ ] 2. Чтение деталей директором

Добавить разрешённое директору чтение через Gateway. Вернуть клиента, ТС, исполнителей, позиции с сохранёнными ценами, итог, статус, этап и состояние справки. Для связанных карточек использовать согласованные права чтения.

**Проверка.** Ответ содержит данные нужного заказа, сохраняет исторические цены после правки каталога и закрыт для ролей без доступа.

---

### [ ] 3. API профиля и параметров уведомлений

Добавить чтение собственного профиля из Users и серверное хранение настройки уведомлений. По исходному ТЗ, когда оно будет доступно, уточнить обязательность восстановления пароля. При включении задачи согласовать канал и контракт восстановления.

**Проверка.** API выдаёт только разрешённые данные и сохраняет настройку для следующих сессий.

## Фронтенд

### [ ] 1. Список справок в вебе клиента

Показать состояния «Формируется», «Готова» и окончательную ошибку по ответу API. Для готовой справки подключить скачивание PDF. Переход из ошибки в диалог поддержки подключить на четвёртом вечере.

**Проверка.** Три серверных состояния отображаются различимо, готовый PDF скачивается из списка.

### [ ] 2. Экран деталей директора

Добавить переход из таблицы и дашборда. Показать данные заказа, состояние справки и разрешённые переходы к связанным карточкам и PDF. [Макет деталей](../../design/web-director/director-web-design_1.md#6-детали-заказа-директорский-просмотр)

**Проверка.** Оба входа открывают один заказ. После редактирования каталога цены и сумма на экране совпадают с карточкой клиента.

### [ ] 3. Экраны профиля

Показать клиенту имя и дату регистрации, инженеру и директору — имя, роль, телефон и дату начала работы. Подключить выход и настройку уведомлений к серверному контракту. Если восстановление пароля входит в объём по ТЗ, подключить согласованную форму. [План фронтенда](../../design/frontend-plan.md)

**Проверка.** Выход завершает клиентскую сессию. После входа отображается сохранённая настройка. Доставку с учётом настройки проверить на пятом вечере.
