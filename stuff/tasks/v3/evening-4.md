# СТО v3 · Вечер 4 — Chat и поддержка

**Итог вечера.** Клиент, инженер и директор обмениваются сообщениями в своих диалогах и видят, когда собеседник их прочитал.

## Бэкенд

### [x] 1. Модель диалогов и HTTP

Подключить Chat, отдельную БД, миграции и маршруты Gateway. Реализовать открытие, список, историю, отправку сообщений и отметку о прочтении. Диалог клиента с инженером привязан к заказу и его ответственному, диалог директора с инженером постоянный, поддержка направляется директору из конфигурации. Проверять участие во всех операциях с диалогом. Для диалогов по заказу действуют правила проверки владельца и текущего ответственного из [ADR-044](../../adr/architecture/ADR-044-order-chat-access.md).

`GOWORK=off make generate test MODULE=chat` прошёл. Генерация завершилась без предупреждений, Go-пакеты Chat скомпилировались как отдельный модуль.

На временном PostgreSQL 18 применили миграцию и проверили запросы sqlc. Все три типа диалогов возвращают прежний ID при повторном открытии и перестановке участников. Другой заказ или ответственный получает отдельный диалог. Сообщение постороннего не записывается, сообщение участника сохраняется непрочитанным.

`make generate generate-frontend-api MODULE='chat orders'` обновил артефакты Go и TypeScript. `make test MODULE='chat orders gateway'` прошёл. `make up SVC=nginx` собрал образы и запустил Chat с отдельной БД. Через nginx прошли `bash scripts/e2e.sh chat-http` и регрессия `bash scripts/e2e.sh director-order`. В `chat-http` проверены три типа диалогов, повторное открытие, приватность, прочитанность до указанного сообщения и доступ после смены ответственного.

**Проверка.** Каждая пара открывает свой диалог, повторное открытие возвращает тот же диалог. Посторонний пользователь не получает историю или список чужих диалогов. После смены ответственного клиент может только читать старый диалог, прежний инженер теряет к нему доступ, текущий видит собственный диалог. ### [x] 2. Доставка через WebSocket

Подключить авторизованный WebSocket через Gateway для новых сообщений и прочитанности. Через HTTP отдавать историю и состояние прочитанности для восстановления после обрыва. [ADR-018](../../v2/adr/architecture/ADR-018-chat-websocket-exception.md)

**Проверка.** Подписчик получает события сообщения и прочтения, посторонний пользователь не получает события. Прежний ответственный перестаёт получать события после смены назначения, включая уже открытое соединение. HTTP выдаёт актуальное состояние после разрыва.

Через nginx прошёл `bash scripts/e2e.sh chat-ws`. Проверены отказ без действительного JWT, отправка и прочтение, отсутствие повторного события прочтения, доступ после смены ответственного и восстановление через HTTP. Тест Chat дополнительно проверяет смену назначения для события, которое уже попало в очередь. Тест Gateway проверяет срок соединения и заголовки Upgrade. Go-тесты и линт Chat, Gateway и Orders прошли.
