# TODO (v2) — отложенные модули

Модули, вынесенные из v1 19.10.2026. Материалы в этом каталоге повторяют раскладку v1.

## 1. Chat

Для диалога клиента по заказу в v3 действуют [ADR-044](../adr/architecture/ADR-044-order-chat-access.md)
и [обновлённая sequence](../v3/uml/sequence-chat-client.drawio).

Решения (08.10.2026), действуют для v2:
- Протокол — ADR-018: отправка `POST`, доставка `WebSocket` через Gateway; RabbitMQ не участвует.
- Модель: `Диалог(тип, участник1, участник2, order_id?)` + `Сообщение(…, прочитано bool)`,
  прочитанность серверная и видна собеседнику.
- Типы диалогов: клиент↔инженер (по заказу, собеседник — ответственный `orders.engineer_id`),
  директор↔инженер (постоянный), поддержка (клиент↔директор, `director_id` из конфигурации
  Chat). Клиент↔директор напрямую, вне поддержки, не общаются.
- Sequence: `sequence-chat-client`, `sequence-chat-engineer`, `sequence-chat-director`.
- Открыто: при горизонтальном масштабировании Chat нужна маршрутизация WebSocket-соединения
  к инстансу (см. ADR-018).

## 2. Reports

- Сервис Reports: таблицы `report_requests` (pending / received / failed) и `reports_[тип]`
  (снапшот), команда через outbox + RabbitMQ в Orders / Users, ответ асинхронным событием,
  retry по таймауту. Sequence: `sequence-report` (общая диаграмма).
- **Не сделаны** отдельные sequence для подтипов «По сотрудникам» и «По справкам/заказам»;
  механика та же, различается запрашиваемый тип данных.
- Экраны: список отчётов (4), детальный просмотр (7).

## 3. Статистика по сотрудникам

Use case «Статистика по сотрудникам», `sequence-employee-stats`, экран «Сотрудники»
(число заказов за месяц и выручка, разворачивание списка заказов по клику). Агрегацию в
исходной диаграмме даёт Reports.

## 4. Поддержка (чат клиент↔директор)

В v1 «Поддержка» — статический экран с контактами директора. В v2 возвращается как диалог типа
`support`.
