# director-web-design (v2)

Экраны директора, вынесенные из v1 (19.10.2026): сотрудники со статистикой, отчёты, чат.
Остальные экраны — `v1/design/web-director/director-web-design_1.md`. Нумерация экранов
сохранена из исходного документа.

## Навигация (полная, v1 + v2)

```
Дашборд · Заказы (Все заказы / Ожидают оплаты) ·
Отчёты (Список отчётов / Сотрудники) ·
Каталог (Товары (склад) / Услуги) · Чат
```

## Экраны

### 3. Список сотрудников
Сервис: Users (список), Reports (статистика по каждому).
Карточки: аватар-инициалы, роль, дата начала работы слева; число
заказов за месяц + выручка справа.
**Клик по карточке разворачивает** список заказов сотрудника прямо на
этой же странице (не переход на отдельный детальный экран) — вложенный
список с отступом, показывающий иерархию, шеврон меняется
`chevron-right` → `chevron-down`.

### 4. Список отчётов
Сервис: Reports.
Фильтр по типу (Все / Выручка / По сотрудникам), кнопка "Сформировать
отчёт". Карточки с иконкой по типу, названием (тип + период), датой
формирования. Пример ошибки формирования — приглушённая карточка,
красная иконка-предупреждение (та же логика, что у справок клиента —
единообразие между certificate и report_requests, оба используют
схожий retry-паттерн).

### 7. Детальный просмотр отчёта
Сервис: Reports. Один параметризуемый макет на все три типа отчёта
(разные колонки таблицы), не три отдельных экрана.
- Шапка: тип отчёта + период, дата формирования, кнопка "Назад".
- Крупное итоговое число сверху (сумма выручки — для "Выручка"; общее
  число заказов — для двух других типов).
- Таблица-разбивка, колонки зависят от типа:
  - Выручка — дата, сумма, число заказов (разбивка по дням периода).
  - По сотрудникам — сотрудник, число заказов, выручка.
  - По справкам/заказам — номер заказа, клиент, сумма, дата.
- Для отчёта в статусе `failed` (после исчерпания retry) — вместо
  таблицы заглушка "Отчёт не сформирован", без числовых данных (нечего
  показывать, данные не были собраны).

### 9. Чат (веб, директор)
Сервис: Chat.
Двухколоночный лейаут — как в клиентском чате (`web-design.md`, экран
5): список диалогов слева, открытый диалог справа.
- Диалоги с инженерами (пара director↔engineer) и пункт "Поддержка"
  — диалоги с клиентами, обратившимися в поддержку (сценарий
  certificate после исчерпания retry). Поддержка — единственный канал
  клиент↔директор; напрямую, вне поддержки, они не общаются.
- В отличие от клиентского списка — **без привязки к заказу** в
  превью: эти диалоги не order-scoped (в отличие от client↔engineer),
  это постоянная переписка на пару директор-инженер.
- Диалоги поддержки — тип `support`, второй участник — директор
  (`director_id` из конфигурации Chat). См. `sequence-chat-director`.
- Окно диалога — та же структура сообщений, что у клиента/инженера
  (свои/чужие сообщения разным фоном), включая видимый статус
  "прочитано" (см. решение по chat-механике — прочитанность серверная
  и видна собеседнику).

> Источник данных дашборда в полной версии — Reports (метрики); в v1 их считает Orders
> (см. v1). При возврате Reports в v1 нужно решить, остаётся ли так.
